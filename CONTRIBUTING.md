# Contributing

Anyone can propose anything. What changes, and how, depends on the kind of change ([governance-v1.md](governance-v1.md), section 3.1).

Status: release 1.0, draft. Interim governance: the founder reviews and merges every pull request (see [GOVERNANCE.md](GOVERNANCE.md)).

## Kinds of change

| Kind | What | How |
| --- | --- | --- |
| Editorial | Typos, clarifications, translations, examples | Open a pull request. Label `editorial`. One review by a maintainer who did not author it. |
| Specification | A new section, a new optional field, a new default | Open a pull request. Label `spec`. It stays open for public comment for at least 14 days. One maintainer review. Changelog entry required. |
| Method | The Genome, a classification rule, a record format, conformity vectors, governance-v1.md | Open an IIP. See [iips/README.md](iips/README.md). Label `method-change` on the pull request that implements it. A method change without an accepted IIP is not merged. |

Not sure which kind? Open a Discussion in Proposals, or an issue with the "Specification proposal" template, and ask.

## Rules for every pull request

- **One version of each document.** Edit the document in place. Do not add `-v2` copies.
- **Changelog.** Every change to a document adds an entry to `CHANGELOG.md` and `CHANGELOG.es.md`. The `translation-changelog` workflow fails without it.
- **Translation.** Every change to a `.md` document comes with the same change in its `.es.md` counterpart, in the same pull request. The workflow warns if the counterpart did not change. If you cannot write Spanish, say so in the pull request and add the label `needs-translation`; a maintainer helps before merge.
- **Vectors.** A change to a record format or a schema updates the conformity vectors under `vectors/`. Label `needs-vectors` until they are in.
- **Language.** US English. Literal, short sentences. No hype. Say "draft" and "planned" where they apply. Nothing that does not exist is presented as existing.
- **Review.** A maintainer who did not author the change reviews it. Protected paths (see [CODEOWNERS](CODEOWNERS)) need a Custodian's review. Interim: the founder.
- **Dependencies.** Code is Python, standard library first. If a dependency is needed, pin it exactly. Dependabot opens update pull requests weekly.

## Sign-off and signatures

- **DCO.** Every commit carries `Signed-off-by: Name <email>` (`git commit -s`). By signing off you certify the [Developer Certificate of Origin](https://developercertificate.org/) 1.1. The `dco` workflow checks every commit in the pull request.
- **Pseudonyms.** A persistent pseudonym is accepted for the DCO sign-off when it is tied to a verifiable signing key: the name in `Signed-off-by` is the one used consistently in the commits you sign, and the key that signs them is registered on your account. The DCO certifies the origin of the contribution, not a legal name. The founder signs as "Seldon" (decision 0003).
- **Signed commits.** The `main` ruleset requires signed commits: GPG, SSH, or Sigstore (`gitsign`). Configure one before you push.

## Agents

Agents are welcome as contributors ([governance-v1.md](governance-v1.md), section 7). An agent:

- commits under its own identity (author name and email of the agent, with "(AI)" in the name), never in a human's name;
- carries a `Signed-off-by:` of the human or organization responsible for it, different from the author;
- labels its pull requests `agent-authored`;
- says it is an AI in the pull request body and in every comment it posts;
- never merges, approves, publishes or holds a secret;
- when it is a co-author of a human's commit, appears in a `Co-Authored-By:` trailer under its own identity.

The `dco` workflow fails an agent commit whose sign-off is the agent itself.

## Code: schemas, vectors and the verifier

- `schemas/` (JSON Schema 2020-12), `vectors/` (conformity vectors, 384 cases, with `vectors/index.json` listing each file's SHA-256 and case count) and `verifier/` (`ilorium-verifier`, Python) are the machine forms of the Evidence Format ([specs/evidence-format-v1.md](specs/evidence-format-v1.md)). Changing a format is a method change: it needs an IIP, and the vectors change in the same pull request (`needs-vectors`).
- Vectors are generated by `tools/gen_vectors.py`, which shares no code with the verifier. Never edit a vector by hand: change the generator, regenerate, and regenerate `vectors/index.json` with `python3 tools/vectors_index.py --write`. Generation is deterministic (ML-DSA-44 in the deterministic mode of FIPS 204); `verifier/tests/test_reproducible.py` fails if the published files differ from what the generator produces.
- The verifier imports only the standard library, `cryptography` and `jsonschema` (`verifier/tests/test_isolation.py` enforces it). It never imports the Probe.
- Before sending a change to code: in `verifier/`, `pip install -e ".[dev]"`, then `python -m pytest`, then from the repository root `ILORIUM_SCHEMAS=schemas ilorium-verifier conformity vectors` (384 of 384 must pass; on an environment without ML-DSA-44 support the affected cases report UNKNOWN, which the vectors expect).
- A new dependency needs a written reason, a compatible license and a review ([engineering/architecture-v1.md](engineering/architecture-v1.md), "Dependencies").
